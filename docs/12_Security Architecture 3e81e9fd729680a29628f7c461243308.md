# 12_Security Architecture

Authentication

Users must authenticate before accessing protected resources.

```mermaid
User
 ↓
Login
 ↓
Authentication
 ↓
Authenticated Session
 ↓
Protected API
```

Authentication options currently discussed:

- Google Login
- Email + Password

The final Phase 1 approach still needs confirmation.

## Authorization

Authentication answers:

- Who are you?

Authorization answers:

- What are you allowed to access?

Example:

```mermaid
User A
 ↓
GET /api/events
 ↓
Only User A's events
```

A user should not be able to retrieve another user's private events simply by changing an ID.

## Input Validation

All user-controlled input should be validated before being processed.

Examples:

- Event title
- Date/time
- Email
- Event ID

## HTTPS

Communication between clients and backend services should use HTTPS.

## Secrets

Sensitive configuration should not be hard-coded into source code.

Examples:

- Database credentials
- Authentication secrets
- API keys

These should be managed through environment variables or an appropriate secrets-management mechanism.
